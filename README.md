# SheetDiff

**See exactly what changed between two spreadsheets — which rows, which cells, old value to new value. Runs entirely in your browser.**

## The problem

Someone sends you an updated spreadsheet. Something changed. Nobody knows what. So you scroll. Or you paste both files into a diff tool built for code, not tables, and drown in thousands of lines of noise.

SheetDiff answers one question: **what actually changed between these two sheets?**

## What it does

- **Matches rows by a key column** (`id`, `email`, `SKU`, …) instead of by position, so an inserted row doesn't turn every following row into a false "changed" result.
- **Shows added rows, removed rows, and changed cells** with the old value, the new value, and the record number on both sides.
- **Flags duplicate keys** with their record numbers and excludes those rows from cell comparison as "ambiguous — cannot match" rather than silently picking one.
- **Compares columns too:** added, removed and reordered columns, plus manual mapping when a column was renamed.
- **Explains ragged rows and parse errors** in plain language, with exact record numbers.
- **Optional comparison toggles**, all off by default: trim whitespace, ignore letter case, treat an empty value as a \"no value" state, numeric-aware compare (`1.0 = 1`).
- **Exports a Markdown report** you can paste straight into a PR or an issue. It always shows both raw values and records exactly which toggles were enabled.

## Privacy

Everything runs in your browser tab. There is no backend, no analytics, and no network calls at runtime. Two spreadsheets are exactly the kind of files that should never leave your machine, and with SheetDiff they don't. You can verify there is no network activity in your browser's DevTools.

## Usage

1. Open the app (hosted, or via `npm run dev`).
2. Add **File A (original)** and **File B (updated)**: drop each on its drop zone, click to browse, or paste text with Ctrl/Cmd + V.
3. If a file was read as one column, pick the delimiter from that file's menu — the diff re-runs instantly. Auto-detection is only a guess.
4. Choose the **key column** to match rows by. SheetDiff suggests one (labeled as a guess — you can change it, and nothing is applied silently) or you can explicitly switch to positional comparison.
5. Optional: map unmatched columns, and turn on any comparison toggles.
6. Export the Markdown report ("Copy report" or "Download .md") and share it.

> **A note on record numbers:** findings refer to *parsed record* numbers (record 1 is the header row), not editor line numbers. If a field contains a newline inside quotes, the numbering shifts from what your text editor shows.

> **A note on Excel files:** only stored cell values are read. Formulas are **not** evaluated — a formula cell shows its last saved result. Trailing empty rows and columns are dropped by the reader.

## What it deliberately does NOT do

- **It never modifies or "repairs" your files.** Comparison only — no rewritten files, no silently dropped rows, no "cleaned" exports.
- **It does not evaluate formulas.** No spreadsheet engine is bundled; only the values already stored in the file are compared.
- **It does not fuzzy-match keys.** `"Ada Lovelace"` and `"ada lovelace"` are different keys unless you explicitly turn on case-insensitive comparison. Nothing is guessed silently.
- **It does not auto-repair your data.** The positional fallback and suggested mappings are always explicit, labeled choices.
- **It does not detect encodings beyond UTF-8 (+BOM).** Other encodings are not reliably detectable from content alone, and this tool does not pretend otherwise.
- **It does not upload anything, ever.** No server, no queues, no AI calls, no "anonymous usage stats".
- **It does not handle files over 5 MB.** Both files are parsed in your browser tab, and the limit keeps it responsive.

## Development

```bash
npm install      # install dependencies
npm run dev      # start the Vite dev server
npm test         # run the unit tests (vitest)
npm run build    # type-check (tsc --noEmit) + production build
npm run preview  # preview the production build locally
```

The xlsx test fixture is generated by `node tests/fixtures/make-xlsx-fixture.mjs` and committed, so tests do not depend on running that script.
